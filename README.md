# 모여요 — 바이브코딩으로 모임 일정 조율 서비스 만들기

> 코딩 전에, 기획부터.
> AI(Claude)와 대화하며 **UI/UX 기획 → 개발 → 배포**까지 진행한 과정을 따라 할 수 있도록 정리했습니다.

운영자 1명이 날짜·시간 범위를 정해 링크를 공유하면, 참가자(최대 10명)가 회원가입 없이 이름과 가능한 시간(30분 단위)을 제출합니다.
가장 많이 겹치는 시간으로 모임을 **자동 확정**하거나 **운영자가 확정**하고, 확정할 시간이 없으면 모임이 **취소**됩니다.

# Part 1. UI/UX — AI와 기획하기

📎 발표자료: `발표자료/모임_일정_조정_서비스_UIUX_발표자료_20261120_v0.2.pptx`

### Step 1. 문제 정의 — 어떤 일을 줄이고 싶은가?

| 현재 | 목표 |
|---|---|
| 운영자가 시간표를 직접 비교하고 결정 | 겹치는 시간을 후보로 제안 |
| 모임 공지 문구도 매번 작성 | 마감 때 자동 확정하거나 운영자가 확정 |

### Step 2. AI에게 요구사항을 말하고 서비스 제안 받기

처음에는 생각나는 요구사항을 문장으로 그대로 적어 보내면 됩니다.

```text
운영자 1명과 참가자 10명까지 사용해.
운영자가 날짜·시간 범위를 정해 링크를 공유하고,
참가자는 회원가입 없이 이름과 가능한 시간(시간은 30분 단위로 선택)을 제출하고,
참가자가 제출한 시간들 중 겹치는 시간으로 모임을 자동 확정하거나 운영자가 일정을 확정할 수 있게 하고 싶어.
확정된 모임의 인원, 참가자 이름을 결과에 보여주고 일정을 캘린더 추가 기능도 있었으면 좋겠어.
확정될 모임이 없거나 마감됐을 때는 모임이 취소되게 해줘.
모임 일정 마감 뒤 서버에서도 제출이 안되게 해야 해.
위 내용을 기반으로 서비스에 만드는 걸 제안해 줄래?
```

AI가 화면 구성, 상태 흐름, 자동 확정·취소 규칙, 서버 처리, 캘린더 추가 방식을 담은 제안서를 돌려줍니다.

### Step 3. UI 시안 만들기

```text
제안된 내용으로 UI를 보여줄래?
```

모바일 화면 시안이 디자인 캔버스에 만들어집니다. 버튼을 누르면 화면 사이를 이동해 볼 수 있습니다.

### Step 4. 시안을 보며 수정 반복하기 (티키타카)

화면을 보면서 느낀 점을 그대로 말하면 됩니다. 실제로 주고받은 요청 예시입니다.

| 다듬은 것 | 요청 예시 |
|---|---|
| 화면 추가 | `모임 목록 화면도 있었으면 좋겠어` / `모임의 Status도 표시되면 좋겠어` |
| 예외 화면 | `참가자 링크는 기한이 지났을 때 보이는 화면이 필요해` |
| 입력 방식 | `시간 선택을 클릭 또는 드래그 선택할 수 있게 해줘` |
| 입력 검증 | `새 모임 만들기에서 날짜 선택하면 달력 표시` / `응답 마감은 모임 시작 날짜 -1일 전까지만 선택 가능` / `각 날짜와 시간 선택에서 시작이 종료보다 크면 안됨` |
| 문구 | `링크가 만들어졌어요 > 모임이 만들어졌어요 로 수정` |
| 디자인 일관성 | `Alert 디자인은 첨부된 이미지와 같이 통일해줘` (캡처 이미지 첨부) |
| 화면 이동 | `4번에서 확정 취소하면 4-A(확정)와 4-B(취소)을 표시해야지` |
| 역할 구분 | `화면명에 참가자 운영자 구분 표시해줘` |

> 💡 **AI가 내가 정하지 않은 규칙을 넣으면 바로 빼 달라고 하세요.**
> 예) 시안에 "응답 기록은 30일 뒤 자동 삭제" 문구가 들어갔을 때 → `그런 규칙은 내가 정하지 않았어. 삭제해줘`

완성된 시안은 운영자 화면 6개, 참가자 화면 5개입니다.

| 운영자 | 참가자 |
|---|---|
| 0 모임 목록 · 1 모임 만들기 · 2 링크 공유 | 3 가능한 시간 제출 · 5 모임 확정 · 6 모임 취소 |
| 4 응답 현황 · 4-A 확정 · 4-B 취소 | 7 응답 기간 만료 · 8 링크 만료 |

참가자는 링크 하나로 상황에 맞는 화면을 봅니다.

| 참가자 상황 | 보이는 화면 |
|---|---|
| 응답 마감 전 | 3. 가능한 시간 제출 |
| 응답함 + 모임 확정 | 5. 모임 확정 |
| 응답함 + 모임 취소 | 6. 모임 취소 |
| 응답 안 함 + 응답 마감 지남 | 7. 응답 기간 만료 |
| 날짜 범위 종료일 지남 (어떤 경우든) | 8. 링크 만료 |

### Step 5. Requirement.md 만들기

```text
여기까지 내용을 마크다운으로 Requirement.md 파일로 생성해줘
파일 내용에는 Flow, IA, 화면별 기능 정의를 표시해줘
```

👉 결과물: [`Requirement.md`](Requirement.md)

**검토 체크리스트**

- [ ] Flow, IA, 화면별 기능 정의, 미결 사항이 빠지지 않았는지 확인
- [ ] AI가 작업 폴더에 만든 Requirement.md를 열어 작성 내용 검토
- [ ] UTF-8 `Requirement.md`인지, `Requirement.md.txt`가 아닌지 확인

> AI의 초안이 아니라 **검토한 파일**이 결과물입니다.

### Step 6. 시안을 HTML로 내보내기 (퍼블리싱 대신)

```text
디자인 시안도 개발할 수 있게 각 화면을 html 파일로 다운로드 할 수 있게 해줘
```

👉 결과물: [`ui-html/`](ui-html) — `index.html`을 열면 전체 화면 목록이 나옵니다. 달력, 드래그 선택, 제출 같은 동작도 시안과 같이 움직입니다.

# Part 2. 개발 — Claude와 만들고 배포하기

📎 발표자료: `발표자료/모임_일정_조정_서비스_개발_발표자료_20261120_v0.2.pptx`

사용 도구: **Claude Code**(Claude 앱의 Code 탭) · **Supabase**(데이터베이스) · **Vercel**(배포)

| 단계 | 내용 |
|---|---|
| STEP 1 | 준비 — Node.js와 Git 설치를 Claude에게 부탁 |
| STEP 2–3 | 요구사항과 코드 — 문서로 정리하고 Claude에게 구현 맡기기 |
| STEP 4–7 | 데이터베이스 — Supabase 프로젝트를 만들고 앱과 연결 |
| STEP 8–11 | 내 컴퓨터에서 테스트 |
| STEP 12 | Git에 저장 |
| STEP 13–15 | Vercel로 인터넷에 배포 |

**준비물**: Claude 앱 하나와 무료 계정 두 개(Supabase, Vercel). Node.js와 Git은 Claude에게 부탁하면 설치해 줍니다.

### STEP 1. 도구 설치는 Claude에게 부탁하기

1. Claude 앱의 **Code 탭**을 엽니다.
2. 아래처럼 입력합니다. Windows 기본 설치 도구(winget)로 공식 배포판을 설치해 줍니다.
   ```text
   Node.js와 Git 설치해 줘
   ```
3. 관리자 권한 창이 뜨면 **예**를 누릅니다.
4. 앱을 다시 켜면 준비 끝입니다.

### STEP 2. 만들 것을 문서 한 장으로 정리하기

Part 1에서 만든 요구사항 문서를 프로젝트 폴더에 둡니다. Claude가 그대로 읽고 구현합니다.

- 누가, 왜 쓰는지 (개요)
- 화면 구성
- 기능과 추천 규칙
- 완료 기준 체크리스트

> 프로토타입 HTML(`ui-html/`)이 있으면 같은 폴더에 함께 두세요.

### STEP 3. 폴더를 선택하고 구현 맡기기

1. 새 세션에서 문서가 든 폴더를 선택합니다.
2. 요청을 입력합니다.
   ```text
   REQUIREMENTS.md를 읽고 이 서비스를 구현해 줘.
   · Next.js + TypeScript + Supabase, 배포는 Vercel
   · 추천 알고리즘은 따로 분리하고 테스트 작성
   · 구글 캘린더는 링크 방식부터
   ```
3. 방식을 물으면 골라서 답합니다.
4. 만든 결과와 테스트 결과를 확인합니다.

Claude가 프로젝트를 만들고, 코드를 쓰고, 테스트와 빌드까지 돌립니다. 예) `schema.sql`(데이터 표·권한·10명 제한), `recommend.ts`(추천 알고리즘 + 테스트), 화면 컴포넌트, `SETUP.md`(연결과 실행 순서 안내)

### STEP 4. Supabase 가입하고 프로젝트 만들기

1. [supabase.com](https://supabase.com) 가입 (GitHub·이메일)
2. 조직을 만들고 **Free** 플랜 선택
3. **New project** — Project name 입력, Database password는 **Generate a password**, Region은 **Northeast Asia (Seoul)**
4. 1–2분 기다리면 준비 완료

### STEP 5. SQL 한 번으로 표와 권한 만들기

1. 왼쪽 메뉴에서 **SQL Editor**를 엽니다.
2. `schema.sql` 내용 전체를 붙여넣습니다.
3. **Run** → 확인 창에서 **Run query**
4. `Success`가 보이면 완료입니다.

### STEP 6. 익명 로그인 켜기

참여자가 회원가입 없이 링크와 이름만으로 들어올 수 있게 해 주는 설정입니다.

**Authentication → Sign In / Providers → Allow anonymous sign-ins** 켜기 → **Save changes**

### STEP 7. 연결 값 두 개를 앱에 알려 주기

**Project Settings → API Keys**에서 Publishable key를 복사해, 프로젝트 폴더의 `.env.local`에 Project URL과 함께 붙여넣고 저장합니다.

```env
NEXT_PUBLIC_SUPABASE_URL=https://[프로젝트].supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_…
```

> ⚠️ **Secret key(`sb_secret_…`)는 넣지 마세요.** 관리자 권한 키라 웹페이지에 들어가면 안 됩니다.

### STEP 8. 내 컴퓨터에서 실행하기

```text
개발 서버 켜 줘
```

브라우저에서 `http://localhost:3000`을 열고 모임을 만들어 봅니다.

### STEP 9–11. 직접 써 보며 테스트하기

- [ ] 이름을 넣고, 칸을 누르거나 드래그해서 가능한 시간을 칠할 수 있다
- [ ] 칠한 칸을 다시 드래그하면 지워진다
- [ ] 여러 사람이 칠하면 히트맵과 추천 시간이 나온다
- [ ] 추천 시간으로 확정하면 확정 카드와 캘린더 추가가 보인다
- [ ] 확정과 취소는 운영자에게만 보인다

> 잘 안 되는 부분은 화면을 보고 느낀 대로 말하거나, 에러 메시지를 그대로 붙여넣어 고쳐 달라고 하면 됩니다. **코딩 → 테스트 → 수정**을 반복합니다.

### STEP 12. 잘 되는 지금, Git에 저장하기

```text
지금 상태 Git에 저장해 줘
```

- 나중에 망가져도 이 시점으로 되돌릴 수 있습니다.
- 키가 든 `.env.local`은 저장 대상에서 자동으로 빠집니다.
- 고칠 때마다 저장하는 습관을 들이세요.

### STEP 13. Vercel 가입하고 Claude와 연결하기

1. [vercel.com](https://vercel.com) 가입, 플랜은 **Hobby(무료)**
2. Team Name에 아무 이름 입력
3. Claude에게 `Vercel에 배포해 줘`
4. 나오는 링크를 열고 **Allow**

### STEP 14. Vercel에도 연결 값 알려 주기

프로젝트 **Settings → Environment Variables → Add Environment Variable** → **Import .env**로 `.env.local`을 불러오고 `NEXT_PUBLIC_` 두 줄만 남깁니다. Type은 **Config** → **Save**.

### STEP 15. 배포하고 링크 공유하기

```text
저장했어, 배포해 줘
```

배포가 끝나면 `https://[내-앱].vercel.app` 링크가 생깁니다. 모임을 새로 만들고 참여 링크를 단톡방에 공유하면, 누구나 회원가입 없이 이름만 넣고 참여할 수 있습니다.

> 코드를 고친 뒤에는 `다시 배포해 줘` 한마디면 반영됩니다.

## 잘 요청하는 법

| 습관 | 설명 |
|---|---|
| 문서로 먼저 정리 | 무엇을, 누구를 위해, 언제 완성인지 적어 두기 |
| 작게 시작하기 | 기본 기능부터 만들고 하나씩 붙이기 |
| 보고 느낌대로 말하기 | "휴대폰에서도 보기 좋게"처럼 말해도 충분 |
| 에러는 그대로 붙여넣기 | 뜻을 몰라도 괜찮아요, 원인은 Claude가 찾아요 |
| 잘 될 때 저장하기 | "Git에 저장해 줘"로 되돌아갈 지점 만들기 |
| 계정과 키는 내 손으로 | 가입과 키 입력은 직접, Secret key는 앱에 넣지 않기 |

> 이제 여러분의 아이디어를 문서 한 장에 적고, Claude에게 말을 걸어 보세요.
